# CodeMind Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A web app that builds a Graphify knowledge graph for any GitHub repo, then answers change-impact questions with Gemini. Answers appear in chat and are highlighted on the graph.

**Architecture:** A Next.js 16 frontend plus `/api/chat` (AI SDK with Gemini tool-calling over a pure-TS graph engine), and a Python Vercel function `api/graph.py` that runs Graphify on a downloaded tarball.

**Tech Stack:** Next.js 16, React 19, TypeScript, Tailwind v4, AI SDK + `@ai-sdk/google`, react-force-graph-2d, Vitest, Python 3.13 + graphifyy + pytest.

**Spec:** `docs/superpowers/specs/2026-11-25-codemind-design.md`

## Global Constraints
- The Gemini key comes from `process.env.Gemini ?? process.env.GEMINI_API_KEY`; model `gemini-2.5-flash`.
- Tarball limit 60 MB; source-file limit 4000.
- No database; the graph is held client-side and sent with each chat request.
- Node ≥ 22.

## Review Focus
- A node name that doesn't exist: impact should return `{found:false, suggestions}` rather than throw.
- Cycles in the graph (A imports B imports A): BFS must terminate, with each node at its minimum depth.
- Repo URL variants (`.git` suffix, `/tree/branch`, trailing slash, `owner/repo`) must parse; garbage should give a 400 error.
- A missing Gemini key: `/api/chat` should return a 500 with a readable message, not crash.
- Large graphs (>3000 nodes): the payload sent to the chat should be compacted (no metadata), and the UI should stay interactive.

### Task 1: Scaffold + graph engine (TDD)
**Files:** Create `lib/graph/types.ts`, `lib/graph/engine.ts`, `lib/graph/engine.test.ts`
**Interfaces (Produces):**
- `type CMNode = {id,label,file?,location?,community?,communityName?,kind}`
- `type CMLink = {source,target,relation}`
- `type CMGraph = {nodes:CMNode[],links:CMLink[]}`
- `normalizeGraph(raw: unknown): CMGraph` turns Graphify's node-link JSON into a `CMGraph`.
- `class GraphEngine(g)` with these methods:
  - `search(q, limit=8): CMNode[]` does fuzzy matching on label, id and file.
  - `impact(q, maxDepth=4): ImpactResult` does a reverse BFS over incoming edges and returns `{found, target, affected:[{node,depth,via}], files, suggestions}`.
  - `neighbors(q)` returns `{incoming,outgoing}`.
  - `path(a,b)` returns node ids, or null.
  - `stats()` returns counts.
- [ ] Tests: search ranks an exact label first. Impact on `connect()` in the sample graph returns `.get()` at depth 1 and `handler()` at depth 2. A cycle terminates. An unknown name gives `found:false` with suggestions. `path` works. `normalizeGraph` maps `source_file` to `file`.
- [ ] Run vitest (expect fail), implement, run vitest (expect pass), commit.
